# 0018. JSON generation, mock images (Pillow), and file/folder batch copying

- Status: Accepted
- Date: 2026-11-22
- Issue: #76

## Context

M4-2 (`json-gen`), M4-3 (`mock-image`), M4-4 (`file-copy`), and M4-5 (`folder-copy`) are tools that write files or directories. `docs/design.ja.md` §4.2 and §9 state that all of them write to the local machine, take optional seeds for generators (`json-gen`, `mock-image`), and require per-target locks (`target_lock`), `--dry-run`, and non-`--dry-run` run history entries.

§5 and §9 did not specify the schema input format for `json-gen`, the image library dependency and `--random-ratio` semantics for `mock-image`, or the numbering format and streaming contracts for `mock-image`, `file-copy`, and `folder-copy`.

## Decision

- `json-gen` writes a UTF-8 (no BOM) JSON array file at `OUTPUT`, accepts a JSON schema path or inline JSON via `--schema` (plus simple `--col NAME:TYPE` definitions) covering all 13 types in §9, uses an immediate POST form in the GUI (pre-filled with a sample schema), acquires `target_lock` on `OUTPUT`, and records non-`--dry-run` runs in `HistoryStore`.
- `mock-image` adds `pillow>=10.1` (HPND license, checked in the [Pillow documentation](https://pillow.readthedocs.io/): `Image.new`, `ImageDraw.Draw`, and `ImageFont.load_default(size=...)`) to `packages/pytoolbox`. It writes numbered images (`mock_001.png`, etc., supporting PNG and JPEG), interprets `--random-ratio` by sampling dimensions up to the given width and height per image, locks its output targets, streams `Progress` and `BatchResult`, and records non-`--dry-run` runs. Rejected: hand-rolling PNG/JPEG encoders in pure Python, which cannot handle JPEG or later support M4-8 (`image-clip`).
- `file-copy` and `folder-copy` expand all target names up front using `--format` (defaulting to `{stem}_{n:03d}{suffix}` and `{name}_{n:03d}`), `--start` (default 1), and `--count`, acquire `target_lock` across every destination path before writing anything, stream `Progress` and `BatchResult` (over SSE in the GUI and stdout in the CLI), and record non-`--dry-run` runs in `HistoryStore`.

## Consequences

`docs/design.ja.md` §5 and §9 carry the screen and specification updates. `docs/conventions.md` (`Toolchain` and `CLI`) records the Pillow dependency and command contracts. Subsequent `feat` Issues implement M4-2 through M4-5.
