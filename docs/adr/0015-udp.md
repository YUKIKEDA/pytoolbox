# 0015. UDP receive: the log line, its limits, and how it stops

- Status: Accepted
- Date: 2026-10-28
- Issue: #58

## Context

M2-6 adds `udp`. `docs/design.ja.md` §9 says it listens on `0.0.0.0`, port 9000 by default, logs each datagram's length, hex, and UTF-8 text, and can be started and stopped. §5 does not say how the screen looks. §4.2 gives System Tools a form, a run button, and a console.

The sources: UDPListener (`udp_listener.py`) listens on `0.0.0.0:9000` with a 1,024-byte buffer and prints the sender, the hex, and the length until Ctrl+C. PyDevToys (`services/udp_service.py`) decodes UTF-8 and logs `[ip:port] text`, and reports only "receive error" when the data does not decode.

An experiment on CPython 3.12.8 on Windows: a 2,000-byte datagram read with a 1,024-byte buffer raised `WinError 10040` instead of being cut short; a 65,535-byte buffer read a 65,507-byte datagram. An experiment in Edge with htmx 2.0.11 and the SSE extension 2.2.4: `hx-on::after-settle` that removes the oldest children kept the last 10 of 30 streamed lines.

## Decision

- The buffer is 65,535 bytes, so every UDP datagram is read.
- One datagram is one line: local time with milliseconds, the sender, the length, the hex, and the text, or `not UTF-8`. Hex and text cover the first 1,024 bytes and note the rest as `(+N bytes)`, because 64 KiB in hex is a line of 131,000 characters. The line shows local time because a receive log is read beside the sending device's clock; `LogEvent` keeps UTC.
- A port outside 1 to 65535 is `InputError`; a port that cannot be bound, such as one in use, is `OperationError`. Both fail before anything streams.
- The screen is §4.2's: the port and Start on the left; `Listening on 0.0.0.0:<port>`, Stop, and the console on the right; the count of datagrams when stopped. The console keeps its last 1,000 lines, because a busy device logs hundreds of thousands of lines in an hour. The CLI's output keeps every line.
- Starting a listener in the GUI stops the one before it, so a forgotten listener does not hold the port.
- The CLI prints only log lines on stdout, so `> log.txt` keeps them, and stops on Ctrl+C with the usual `130`. Rejected: exit `0` on Ctrl+C, which would add an exception to the one exit-code rule.
- Tests replace the socket; a unit test opens none.

## Consequences

`docs/design.ja.md` §5 and §9 carry the decision. `docs/conventions.md` (Results, Streaming, Tests, CLI, GUI HTTP) holds the details. #59 builds it. On first use, Windows Defender Firewall may ask whether Python may receive on the network; the tool does not change that.
