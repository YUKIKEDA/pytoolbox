# 0019. PDF split (`pypdf`), file merge, image clip, and cache cleanup

- Status: Accepted
- Date: 2026-11-22
- Issue: #82

## Context

M4-6 (`pdf-split`), M4-7 (`file-merge`), M4-8 (`image-clip`), and M4-9 (`cache-clean`) are the remaining write/delete batch tools. `docs/design.ja.md` §4.2 and §9 state that all of them modify files or directories on disk and therefore require `--dry-run`, per-target locks (`target_lock`), and non-`--dry-run` history entries (`HistoryStore`).

§5 and §9 left open the PDF library choice, exact CLI arguments, streaming vs immediate forms, how `file-merge` reports unreadable files alongside `BatchResult`, how `image-clip`'s GUI preview interacts with crop coordinates, and how `cache-clean` connects to streaming and history.

## Decision

- `pdf-split` adds pure-Python `pypdf` (BSD-3-Clause, checked in the [pypdf documentation](https://pypdf.readthedocs.io/): `PdfReader` and `PdfWriter.add_page`) to `packages/pytoolbox`. It writes one page per file (`page_{n}.pdf`, 1-based), locks all planned destination files up front, streams `Progress` and `BatchResult`, and records non-`--dry-run` runs in `HistoryStore`.
- `file-merge` (`pytoolbox file-merge INPUT [INPUT ...] --output-dir DIR [--sep FMT] [--overwrite] [--dry-run]`) writes UTF-8 (no BOM) to `merged_YYYYMMDD_HHMMSS.txt` with default separator `--- {name} ---`. Unreadable inputs stay non-fatal: their failure reason is written inline at their section in the merged text and also recorded in `BatchResult.failures`, while `Progress` streams per input file.
- `image-clip` (`pytoolbox image-clip INPUT_DIR --box X1,Y1,X2,Y2 [--output-dir DIR] [--overwrite] [--dry-run]`) crops `jpg`, `jpeg`, `png`, `bmp`, and `gif` files via Pillow's `Image.crop`, clamping coordinates to each image's `[0, width] x [0, height]`, saving JPEG at `quality=95`, and defaulting output to `INPUT_DIR` with the `cropped_` prefix. The GUI displays a preview of the first image in the folder whose drag selection stays synchronized with the coordinate inputs, and streams `Progress` and `BatchResult`.
- `cache-clean` (`pytoolbox cache-clean TARGET [TARGET ...] [--dry-run | --apply]`) keeps the explicit 6-target contract from [ADR 0006](0006-cache-clean.md), defaults to `--dry-run` (GUI `Apply` checkbox unchecked by default), streams `Progress` and `BatchResult`, locks target roots, and records history only when `--apply` is used.

## Consequences

`docs/design.ja.md` §5 and §9 carry the screen and specification updates. `docs/conventions.md` (`Toolchain` and `CLI`) records the `pypdf` dependency and command contracts. Subsequent `feat` Issues implement M4-6 through M4-9.
