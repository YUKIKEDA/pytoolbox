# 解説（アーキテクチャ・安全設計・スコープ判断）

`pytoolbox` と `pytoolbox-gui` のコンセプト、構造上の理由、安全性とセキュリティ上の設計判断を解説します。個々のコマンド引数や画面の細目は [リファレンス](reference.md) を参照してください。

---

## 1. コンセプト

エンジニアの日常を支える **「PC運用管理」** と **「開発ユーティリティ（DevToys互換）」** を1つの基盤に集約したスイスアーミーナイフ型ツールボックス。
コアエンジン `pytoolbox`（CLI・Pythonライブラリ）と、Web GUIラッパー `pytoolbox-gui`（ブラウザUI）で構成する。

### 実装言語の方針

- **原則 Python 優先**: 移植性、テストのしやすさ、型安全性を考慮し、機能は原則 Python で実装する。
- **ネイティブシェル（Bash / PowerShell）の限定利用**: OS 固有の低レイヤー操作、複雑なパイプライン処理、環境変数の一括適用など、Python では実装が煩雑になる領域にのみシェルスクリプトを併用する。

---

## 2. 2 系統の実行アーキテクチャ

このプロジェクトのツールは大きく **Developer Utilities**（開発ユーティリティ）と **System Operations**（PC 運用管理）の 2 系統に分類されますが、この分類は **利用者にとって扱う対象の違い（サイドバーと `pytoolbox list` の整理）** のためのものであり、CLI のコマンド体系は `pytoolbox <tool>` の 1 段で統一しています。

```text
[ ユーザー操作 ]
   │
   ├──▶ ① CLI 直接実行 : pytoolbox <tool>
   │
   └──▶ ② Web ブラウザ : pytoolbox-gui (http://127.0.0.1:8000)
              │
              ▼ (pytoolbox コア共有ライブラリ)
       ┌──────────────────────────────────────────────────────────┐
       │ 【パス A】即時応答型 (text-count, resx-compare, ping 等) │
       │  ・1 回の呼び出しで即座に結果を返す                      │
       ├──────────────────────────────────────────────────────────┤
       │ 【パス B】進捗・停止あり型 (コピー/分割/走査/掃除/UDP)   │
       │  ・CLI は標準出力/標準エラーへ進捗・ログを流す           │
       │  ・GUI は SSE リアルタイム配信＋Cancel ボタン            │
       └──────────────────────────────────────────────────────────┘
```

### なぜ実行方式と分類が一致しないツールがあるのか

- **フォルダ走査型 DevTool（`hardcoding`）**: 分類上は Developer Utilities ですが、大きなフォルダの走査は数百秒かかるため、入力ごとに再実行できません。そのため入力欄・Start ボタン・進捗・Cancel を持つパス B として動かします。
- **診断系 System Tool（`ping` / `port`）**: 分類上は System Operations ですが、短時間で単発の結果を返すため、GUI ではパス A の即時応答フォームになっています。
- **正規表現の別プロセス実行（`regex`）**: Python 標準の `re` エンジンはマッチングを C 言語側で連続実行するため、バックトラック爆発が起きた際にスレッド単位のキャンセルや `Ctrl+C` が効きません。そこで CLI・GUI とも別プロセスの Worker で照合します。GUI は打鍵ごとに照合するため 1 秒で打ち切って CPU 枯渇を防ぎ、CLI は重い入力への利用を妨げないよう無期限で回し `Ctrl+C` で Worker を終了させます（外部コマンド用 Runner とは別機構です）。
- **シェルスクリプトの位置づけ**: `runner` は外部コマンドやシェルスクリプトを安全に実行する基盤（`shell=True` 禁止・配列渡し）として用意されています。Python で完結できる処理はインプロセスで `cancel` を確認しながら動かし、OS コマンド呼び出し（`ping` など）やスクリプトが必要な箇所だけ `runner` を通します。

## 3. 書く・消すツールの安全設計

単なる読み取り・整形ツール（`text-count`, `regex`, `resx-compare`, `hardcoding`, `folder-size`, `port`, `ping`, `udp`）と異なり、ローカルディスクへ書き込む／削除するツールはすべて 3 つの防波堤を共有します。

1. **実行前プレビュー（`--dry-run`）**: 何がどこに作られ／消されるかを事前に確認できます。特に削除を行う `cache-clean` は既定自体を `--dry-run` とし、`--apply` を明示しない限り消しません。
2. **書き先ごとの排他ロック（`target_lock`）**: ロックファイル（`<state_dir>/locks/<sha256>.lock`）を用いて、同じファイルや出力先へ複数プロセス／タブから同時に書き込む競合を事前に `OperationError` で止めます（`file-copy` や `pdf-split` 等では展開される全出力先をまとめてロックします）。
3. **消せない実行履歴（`HistoryStore`）**: 書く・消す操作の実行結果（`--dry-run` を除く）は `<state_dir>/history.sqlite3` に残ります。あとからトラブル原因や実行引数を追跡できるよう監査ログとして設計しており、GUI の **Logs & History** 画面にあえて一覧消去（Clear）ボタンを置いていません。

## 4. ローカル Web GUI の設計とセキュリティ境界

`pytoolbox-gui` はローカルファイル削除やコマンド実行を伴うため、一般の SPA（JSON API＋ビルド済み JS）とは異なる割り切りをしています。

- **HTMX + SSE によるハイパーメディア構成**: FastAPI サーバーが最初から描画済みの HTML 断片を返し、HTMX がページの一部を差し替えます。JSON データ API（`/api/...`）を持たないため、プログラム連携は一貫して CLI と Python コアライブラリを使います。
- **副作用を `GET` に置かない**: ブラウザの先読み（prefetch）やリンク再訪問で意図せずツールが走るのを防ぐため、ツールの実行は必ず `POST` に限定し、`GET` は画面表示・検索（`/search`）・履歴表示（`/history`）・SSE 購読のみに閉じ込めています。
- **ローカルホスト境界の防御（`403`）**:
  - DNS リバインディング攻撃を防ぐため、`Host` ヘッダが `127.0.0.1:<port>` または `localhost:<port>` 以外のリクエストをすべて拒否します。
  - 他サイトからの CSRF を防ぐため、すべての `POST` で `Origin` ヘッダが `http://127.0.0.1:<port>` または `http://localhost:<port>` であることを検証し、CORS ヘッダは返しません。
- **完全オフライン動作（CDN 不使用）**: ネットワーク診断（`ping`, `port`, `udp`）は回線トラブル時にも使うツールであるため、HTMX・SSE 拡張・CSS・Fluent UI System Icons をすべてパッケージ内に静的同梱し、インターネット接続なしで起動・動作するようにしています。

## 5. 意図的にスコープ外とした機能

設計と安全性の観点から、以下の機能はあえて実装対象外としています。

- **任意スクリプトの指定実行・自動検出**: シェルスクリプトは各ツールが内部的に `runner` 経由で呼び出す実装手段であり、利用者に直接スクリプト名やパスを実行させたりディレクトリから自動検出したりする入口は作りません（[ADR 0008](adr/0008-cli-safeguards-order.md)）。
- **PC ログイン時のバックグラウンド常駐とグローバルショートカット**: ツール単位の有効／無効切り替えや常駐待機プロセスを持たないワンショット CLI ＋ オンデマンド Web GUI の構成を維持します（[ADR 0008](adr/0008-cli-safeguards-order.md)）。
- **`json-format`、`base64`、`uuid` 生成**: 日常用途に対して個別コマンドとして抱える必要性が薄いため対象から外しています（[ADR 0012](adr/0012-no-json-format-base64-uuid.md)）。
